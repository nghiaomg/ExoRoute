## Context

Bạn muốn ExoRoute hỗ trợ các provider liên quan đến **Devin (Cognition)** như 9Router và OmniRoute. Kết quả thám hiểm cả 2 repo + docs chính thức:

- **9Router** (`devin-cli`): spawn tiến trình `devin acp` cục bộ, JSON-RPC ACP qua stdio, xuất OpenAI-style SSE. Auth từ `devin auth login` của CLI.
- **OmniRoute**: `devin-cli` (ACP stdio, có thể inject `WINDSURF_API_KEY`), `devin-cli-agentic` (ACP, output Anthropic-style), `devin-desktop` (Connect-RPC protobuf tới `server.codeium.com`, key Windsurf, reverse-engineered), `devin` cloud agent (`https://api.devin.ai/v1` Bearer — REST quản lý phiên, KHÔNG có chat API).
- **Cognition không có chat endpoint OpenAI/Anthropic-compatible công khai** — chỉ có: CLI ACP, backend Windsurf (protobuf), và REST quản lý phiên.

Bạn chọn triển khai **cả 3 kiểu**. Kế hoạch chia 3 deliverable độc lập, mỗi cái một commit (hoặc chuỗi commit) riêng, thứ tự theo giá trị/khả thi:

1. **D1 — Devin CLI provider (ACP stdio)** — provider model routing thật (SWE-1.x, Claude, GPT, Gemini theo subscription Devin). Lớp transport non-HTTP đầu tiên của ExoRoute.
2. **D2 — Devin Cloud API task manager** — tính năng dashboard riêng quản lý phiên Devin (tạo/poll/message), API chính thức.
3. **D3 — Devin Desktop adapter (Windsurf backend)** — experimental, dễ vỡ nhất, làm cuối.

Kiến trúc ExoRoute hiện tại (đã xác minh): mọi adapter qua reqwest + egress validation (`src/gateway/execution/target_preparation.rs:198` → `send.rs::send_request` → `request.send()`); `reqwest` đã bật feature `stream` (Cargo.toml:29) nên có thể tổng hợp `http::Response` (200 + SSE body) → `reqwest::Response::from()` để pipeline classify/streaming phía sau **không đổi**. Preset thêm mới qua `data/provider-presets.yaml` (validate build-time trong `build.rs:85-269`); adapter registry mảng tĩnh (`registry.rs:19-61`, phải bump độ dài 41); checklist file từ commit `a77e578` (Vertex).

## D1 — Devin CLI provider (ACP stdio)

### Thiết kế
- **Preset** `devin_cli` trong `data/provider-presets.yaml`: `adapter_id: devin_cli`, category cùng nhóm với các preset CLI-credential hiện có (openai_codex/kilocode), `default_auth_type: none` (dựa vào `devin auth login` của user — auth kiểu 9Router), `default_supported_protocols: [chat_completions]`, `protocol_selectable: false`, `model_discovery: false`, `default_base_url: devin://acp/stdio` (build.rs thêm ngoại lệ HTTPS cho preset có capability stdio — URL này chỉ là định danh, không bao giờ được fetch).
- **Adapter** `src/provider_adapters/devin_cli/`:
  - **Transport mới, spawn mỗi request** (mô hình của cả 2 router): mỗi gateway request spawn `devin acp --agent-type summarizer` (summarizer = không có tool file/shell — **an toàn hơn mặc định 9Router**, theo OmniRoute), handshake ACP `initialize` → `session/new {cwd, mcpServers: [], model}` → `session/prompt {prompt: [{type:"text"...}]}` (đúng format Devin 3000.2.x — `mcpServers` bắt buộc, `prompt` là mảng), đọc `session/update` → `agent_message_chunk`, kết thúc khi `session/prompt` trả kết quả hoặc `agent_stopped`.
  - **Luồng ra**: chuyển delta thành OpenAI `chat.completion.chunk` SSE → tổng hợp `http::Response` (200, `content-type: text/event-stream`, body = `reqwest::Body::wrap_stream`) → `reqwest::Response::from` → toàn bộ classify/streaming/retry của gateway chạy như upstream OpenAI thường. Conversation nhiều lượt flatten thành 1 prompt với marker `[System]/[User]/[Assistant]` (cả 2 router đều làm vậy).
  - **Hook trait**: thêm 1 hook `upstream_transport()` (mặc định `Http`) vào `ProviderAdapter` + capability flag tương ứng trong `AdapterCapabilities` (build.rs schema + `tests/registry_catalog.rs`); `send.rs` rẽ nhánh duy nhất khi transport ≠ Http.
  - **Test không cần Devin CLI thật**: tách phần giao thức ACP (framing ndjson, session lifecycle, chunk conversion) thành hàm thuần/nửa-thuần nhận `AsyncRead+AsyncWrite`; integration test dùng `tokio::io::duplex` với kịch bản ACP script (pattern "scripted raw responses" như `src/support/mock_upstream.rs` nhưng cho stdio).

### Bảo mật (bất biến phải giữ)
- Spawn **không shell** (`Command::args` cố định), binary discovery: env `EXOROUTE_DEVIN_BIN` → đường dẫn chuẩn known (%LOCALAPPDATA%\devin\cli\bin\devin.exe / ~/.local/share/devin/bin/devin / ~/.devin/bin/devin) → PATH; không tìm thấy → lỗi config rõ ràng (không fallback HTTP).
- Env child: kế thừa nhưng **scrub** `ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN`, `OPENAI_API_KEY`… (bài học `CLAUDE_ENV_BLOCKLIST` của OmniRoute); **không inject** key bừa (gây `-32000 invalid api key`).
- **Giới hạn song song**: semaphore toàn cục cho số ACP session đồng thời (pattern `admin_upstream_event_streams`), đầy → target failure có message rõ.
- **Huỷ/timeout**: `kill_on_drop(true)` + guard RAII — client ngắt kết nối/future drop → child bị kill; overall timeout (mặc định 10 phút, cấu hình được) → kill + lỗi; output cap (1 MiB như OmniRoute) chống leak bộ nhớ.
- **Không auto-approve permission** — summarizer không request quyền; nếu upstream vẫn hỏi → fail request với message (không bao giờ tự `bypass` như 9Router).
- Ghi chú rõ trong mô tả preset: provider chạy cục bộ, yêu cầu Devin CLI + login.

## D3 — Devin Desktop adapter (experimental)

- **Preset** `devin_desktop` + adapter `src/provider_adapters/devin_desktop/`: HTTP thuần tới `https://server.codeium.com` (qua egress validation bình thường), endpoint `.../GetChatMessage`, auth preflight `.../GetUserJwt` (key đưa vào protobuf `Metadata`, JWT trả về kèm request chat — **không** đặt key vào header).
- **Protobuf tự viết không thêm dep** (giống OmniRoute, chỉ encode/decode field cố định; Content-Type `application/connect+proto`, frame = 1 byte flag + u32 BE length; gzip frame hỗ trợ decode).
- **Hook có sẵn**: `wants_event_stream` + `allows_missing_event_stream_content_type` + `read_event_stream` (`mod.rs:533`) để decode frame protobuf → tạo SSE `chat.completion.chunk` cho pipeline; model pass-through (không catalog công khai), reasoning → `reasoning_content`.
- **Gắn nhãn experimental** trong mô tả preset: User-Agent `windsurf/<version>`, protocol không chính thức, có thể vỡ khi Cognition đổi backend; version cấu hình qua env.
- Ưu tiên mock-upstream tests (scripted connect frames trong `src/support/mock_upstream.rs`).

## Không làm
- Không auto-approve quyền cho agent, không persistent daemon, không OAuth import cookie Windsurf.
- Không thêm dep mới (ACP dùng tokio process có sẵn; protobuf encode tay). Nếu bắt buộc phải thêm, báo lý do riêng trước khi thêm.
- Không đụng các file theme đang dirty của session khác; locale thêm key bằng patch surgery như các lần trước.
- Không đổi hành vi egress cho các adapter HTTP hiện có.
